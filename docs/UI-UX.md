# UI / UX requirements and design system

## Experience principles
Friendly, understated, highly legible. It should feel like a polished casual board game, not an admin dashboard. Primary flows take few clicks. Show clear status rather than technical error codes. No dark patterns or animations that slow play.

## Aesthetic baseline (modifiable tokens)
- Background: ivory `#F8F6EF`; surface `#FFFFFF`; dark text `#263A35`.
- Accent: deep sage `#327765`, hover `#245D50`; secondary pale teal `#D8EAE5`.
- Tile: warm sand `#F0D6A1`; tile text `#4B3725`; premium squares distinct subdued hues and visible abbreviations.
- Invalid: restrained red `#B33F3F`; positive `#267552`.
- Type: modern open-source sans, distinct numeric score style; scalable through rem. Respect browser font scaling.
- Shadow/rounding: gentle 10-16px rounding on cards, subtle tile elevation, no heavy gradients.
- Theme: light only v1, dark possible later.

## Screen requirements
Welcome: nickname remembered for session; inviting headline, primary Create and secondary Join; inline code input. If joining via invite, preload room and show one clear Join action.
Lobby: invite link and code with copy, connected roster, host designation, start button disabled with a clear reason until a second player joins, lock/unlock room toggle, a short hint under each action, and sharing through the device share sheet where supported.
Game desktop: board central, scores and actions adjacent, rack anchored near bottom, small contextual latest-play message. Mobile: board fills remaining viewport with independent pan and pinch zoom; rack and Play/Recall remain visible; score strip compact, collapsible menu for secondary actions. Avoid full-page horizontal scrolling.
Results: standings with names, score, reason, optional dictionary highlights, New Game and Exit.

## Controls
- First-class tap-to-select rack tile then tap board cell. Drag-and-drop as enhancement. Support keyboard rack/cell navigation and Enter/Space placement.
- Prevent accidental board pan while intending tile placement via clear modes or touch handling. Auto-scroll placed tile into view.
- 44x44 CSS pixel hit-target recommendation where practical; zoom-in available when board cells are visually smaller; focus ring, label and feedback for every action.
- User can Recall all pending placements or individually remove, Shuffle rack, choose blank letter in a dialog/sheet, exchange selected tiles (confirmation), pass (confirmation).
- Turn indicator prominent; optional countdown readable without continuous WebSocket tick. Timer at risk should use color + icon/text, not color alone.
- Provisional score clearly marked estimated; confirmed score only after server commits.
- Word detail on accepted word: source-attributed definition, show missing definition gracefully; don't block scoring.

## Loading/error states
Joining, copying, fetching definitions, reconnecting, validating move, timer expired, invalid word (name word), room full, expired room, invalid token, server quota reached, API unavailable. Each message actionable and human-readable. Do not spam toast notifications. Maintain provisional placement on recoverable validation failure.

## Responsiveness/accessibility
Test 320, 375, 430, 768, 1024, 1440 px; touch devices and desktop keyboard. WCAG 2.2 AA target; text contrast, ARIA live regions with restraint, logical focus, reduced motion, no unannounced focus jumps. Bonus cells show TW/DW/TL/DL and hover/tap legend. Large board uses zoom-to-fit on initial render, zoom +/- and recenter controls, optional mini map; make rack legible at all board sizes.

## Visual acceptance gate
Capture real screenshots at phone 375x812, tablet 768x1024, desktop 1440x900 for Welcome, Lobby, Active Turn, Waiting, Invalid Move, Results. Manually inspect board legibility, overflow, touch access, focus order, tap/drag distinction. Avoid placeholder icon soup or autogenerated generic dashboards.
